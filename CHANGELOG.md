# Changelog

## 0.2.0 — 8 November 2026 — draft

- Made accessible UX design and branding systems explicit planned capabilities in both runbooks and shared workflows.
- Added foundation/manual/automatable coverage, component design/technical/method/reference/user ACT-style relationships and an assurance-plan template.
- Added all six inclusive brand purposes, preserving brand identity and evaluating communication/usability separately from conformance.
- Added route R15, gate G06 and two QA source routes (33 total); retained existing source IDs and histories.
- Existing 0.1.0 adopters should inventory these capability gaps and update affected plans/decisions; no real adoption is assumed.


## 0.1.0 — 8 November 2026 — draft

- Authored employee and customer runbooks over a shared nine-stage programme cycle.
- Added human/AI responsibilities, decision routes, source-change handling and reporting.
- Added 31 reference routes at retrieved repository commits, without copying specialist guidance.
- Added machine-readable workflow definitions, blank templates, a programme-design prompt and two synthetic examples.
- Added acceptance walkthroughs and a structural checker with positive/negative record fixtures.
- Extended the initial assessment classes with `inconclusive` and `tool_error` so uncertainty and execution errors remain explicit. Raw source vocabularies must be preserved through documented mappings.
- Independent review, organisational adoption, pilot evaluation, named maintenance and distribution licence selection remain pending. No remote repository or operational integration is created by this package.

No prior adopted framework version exists; there is no migration required from an approved release. Source-use records in real programmes must establish their own decision baselines.
